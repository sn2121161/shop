## 开通与配置

1. 打开[快递鸟控制台](https://biz.kdniao.com/)，注册并按平台要求完成认证。
2. 申请/开通“在途监控免费版”中的即时查询能力，核对账户权限与 RequestType `1002`。不要误购付费套餐；如果平台给出的免费资格或产品权限与公开文档不同，以开通页面为准。
3. 在“我的服务”查看用户 ID（EBusinessID）与 API Key。
4. 填入服务器或本机的 `backend/.env`（项目已准备空字段，不覆盖已有值）：

```dotenv
KDNIAO_EBUSINESS_ID=你的用户ID
KDNIAO_API_KEY=你的APIKey
```

5. 重新创建后端容器以读取文件：

```bash
docker compose up -d --force-recreate --no-deps api
```

本次开发代码更新首次需先 `docker compose up -d --build --no-deps api frontend`。凭证只保留在后端，不能写进 `frontend/.env.local`。本项目不会代替用户提交个人资料、接受协议、购买套餐。

## 实现与验证边界

- `/api/tracking/options` 返回服务是否已配置与快递商覆盖，不返回任何凭证。
- 登录用户通过 `POST /api/tracking/query` 查询，运单号不放在本站 URL 或数据库中；响应设置 `Cache-Control: no-store`。
- 后端按官方文档进行表单 POST 与 MD5/Base64 签名，只允许固定的 HTTPS 服务地址。
- 每位用户的查询结果在内存缓存 5 分钟，最多 256 条，减少重复消耗额度；重启清空。不同用户不会共享结果缓存，网络请求串行执行并限速。
- 返回轨迹在本站按时间倒序显示。无轨迹、凭证未配置、权限/额度异常、网络失败与格式异常均分别处理，不用模拟数据冒充真实物流。
- 已用隔离测试验证签名、数据转换、缓存、鉴权、无数据与失败路径。没有有效凭证和真实运单前，不能宣称真实物流查询已开通。

### 服务端提示“没有可用套餐”

2026-10-27 使用已配置凭证和用户提供的申通运单复现，服务商返回 `Success=false`、`Reason=业务错误[没有可用套餐]`。这表明账号对当前即时查询请求没有可用套餐；不能将填好 API Key 等同于开通查询服务，也不能因此宣称运单无效或没有轨迹。

请在快递鸟控制台核对与当前用户 ID 对应的免费服务是否已开通、是否有效，以及是否包含即时查询指令 `1002`。代码不会为绕过权限错误而尝试收费接口或购买套餐。服务端权限生效后直接重试即可；仅更换凭证时需要重新创建后端容器。

当前失败处理区分快递商与单号不匹配、单号格式、无轨迹、凭证、查询权限、额度、有效期及未知失败。日志只记录快递商和错误类别，不记录完整单号、密钥和服务商原始错误。未知错误不再直接归因为授权/额度问题。
